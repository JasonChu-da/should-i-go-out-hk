# 「香港現在適合出門嗎？」評分機制說明書

更新日期：2026-08-10｜程式基準：Git `fc20b67`

## 1. 報告範圍

本報告按目前實際程式碼整理，不是重新設計評分規則。核對範圍包括：

- `lib/scoring/score.ts`：計分流程、因素合併、上限、結論及建議排序
- `lib/scoring/thresholds.ts`：所有數值門檻及天氣警告規則
- `lib/outlook/scoring-input.ts`：正規化資料轉成評分證據的方法
- `lib/normalization/*`、`lib/freshness.ts`：地區取值、資料有效性及新鮮度
- `tests/scoring.test.ts`、`tests/aggregate.test.ts`：邊界值及端到端計分行為

這套分數是本站的確定性產品規則，不是香港天文台、環境保護署或醫療機構發布的官方「外出分數」。

## 2. 一句話總結

每個活動模式由 10 分開始；降雨只選一個最嚴重的證據扣一次分，其他適用風險則累加扣分，然後把結果限制在 0–10 分，最後再套用天氣警告或資料不完整所造成的最高分上限。

計算式為：

\[
S_{raw}=\max\left(0,\min\left(10,10-\sum P_i\right)\right)
\]

\[
S=\min\left(S_{raw},C_1,C_2,\ldots,10\right)
\]

其中 \(P_i\) 是各項實際採用的扣分，\(C_i\) 是警告或資料狀態觸發的最高分上限。所有輸出都是整數分。

## 3. 三種活動模式

| 模式 | 直接參與評分的資料 |
| --- | --- |
| 一般外出 | 降雨、氣溫、紫外線、AQHI、天氣警告；高溫與高濕可額外互動扣分 |
| 跑步／踩單車 | 降雨、氣溫、濕度、紫外線、AQHI、天氣警告；高溫與高濕可額外互動扣分 |
| 晾衫 | 降雨、濕度、本港天氣預報文字、天氣警告 |

晾衫模式不使用氣溫、紫外線或 AQHI。一般外出不直接按濕度扣分，但新鮮濕度可與高溫共同觸發額外扣分。

## 4. 數值扣分表

表內依次為「一般外出／跑步或踩單車／晾衫」扣分；未列出的較低數值扣 0 分。

### 4.1 過去一小時觀測雨量

| 雨量 | 扣分（一般／運動／晾衫） |
| --- | --- |
| \(0\) mm | 0／0／0 |
| \(0 < r < 2.5\) mm | 1／2／7 |
| \(2.5 \le r < 10\) mm | 3／4／9 |
| \(10 \le r < 30\) mm | 7／8／10 |
| \(r \ge 30\) mm | 9／10／10 |

### 4.2 未來降雨臨近預報

每個仍未完結的半小時預報時段，只要雨量不少於 0.5 mm 就成為候選。開始時間在現在起 60 分鐘內（包含剛開始、進行中及剛好 60 分鐘後）的候選使用「一小時內」規則，其餘使用「較後」規則。

| 完整半小時預測雨量 | 一小時內 | 較後 |
| --- | --- | --- |
| \(0.5 \le r < 2.5\) mm | 1／2／7 | 0／1／5 |
| \(2.5 \le r \le 5\) mm | 2／3／8 | 1／2／6 |
| \(r > 5\) mm | 3／5／9 | 2／3／7 |

注意：程式明確把「剛好 5 mm」放在中間級別，只有大於 5 mm 才進入最高級別。進行中的半小時仍按該完整半小時雨量評估，不會按剩餘分鐘比例縮小。

### 4.3 晾衫文字預報

這項只適用於晾衫：

| 經有限詞組比對得到的預報級別 | 扣分 |
| --- | --- |
| 較大雨勢：例如「雨勢較大」、「大雨」、「暴雨」、「狂風雷暴」 | 7 |
| 驟雨／有雨／雷雨／雷暴 | 3 |
| 沒有命中，或只出現「沒有雨」、「無雨」 | 0 |

負面詞組會先移除，避免「沒有雨」被「有雨」誤判。這不是任意自然語言推論，而是固定、受測試覆蓋的詞組清單。

### 4.4 降雨不重複累加

過去一小時觀測、四段未來半小時預報，以及晾衫文字預報都先各自產生候選，最終只採用扣分最高的一項 `rain-risk`。四段 nowcast 不互相累加，不同來源也不互相累加。

扣分相同時依次選擇：

1. 有明確生效時間者；
2. 較接近現在者；
3. 仍相同時依 nowcast、即時觀測、文字預報排序。

未被選中的雨量來源只可作說明證據，不再扣分。

### 4.5 氣溫

晾衫模式不計氣溫。

| 氣溫 | 扣分（一般／運動） |
| --- | --- |
| \(t < 28\,^\circ\mathrm{C}\) | 0／0 |
| \(28\,^\circ\mathrm{C} \le t < 30\,^\circ\mathrm{C}\) | 1／2 |
| \(30\,^\circ\mathrm{C} \le t < 33\,^\circ\mathrm{C}\) | 1／3 |
| \(33\,^\circ\mathrm{C} \le t < 35\,^\circ\mathrm{C}\) | 3／6 |
| \(t \ge 35\,^\circ\mathrm{C}\) | 5／8 |

### 4.6 濕度

一般外出沒有獨立濕度扣分；下表只適用於運動及晾衫。

| 相對濕度 | 扣分（運動／晾衫） |
| --- | --- |
| \(h < 70\%\) | 0／0 |
| \(70\% \le h < 85\%\) | 0／1 |
| \(85\% \le h < 95\%\) | 2／3 |
| \(h \ge 95\%\) | 3／5 |

若氣溫及濕度均為新鮮資料，而且 \(t \ge 33\,^\circ\mathrm{C}\) 及 \(h \ge 85\%\)，一般外出額外扣 1 分，運動額外扣 2 分；晾衫沒有這項互動扣分。

一般外出只有在新鮮氣溫達 \(33\,^\circ\mathrm{C}\) 或以上時，濕度才成為高溫互動所需的風險資料。此時若濕度缺失、過時或格式異常，程式會把濕度列入 `ignoredFactors`，並因資料不完整把總分最高限制為 7；氣溫低於 \(33\,^\circ\mathrm{C}\) 時，缺少濕度不會單獨觸發這項限制。

### 4.7 紫外線指數

晾衫模式不計紫外線。夜間 UV 狀態為 `notApplicable`，不扣分，也不觸發資料不完整上限。

| UV 指數 | 扣分（一般／運動） |
| --- | --- |
| \(u < 3\) | 0／0 |
| \(3 \le u < 6\) | 0／1 |
| \(6 \le u < 8\) | 1／2 |
| \(8 \le u < 11\) | 2／4 |
| \(u \ge 11\) | 3／6 |

### 4.8 AQHI

官方 `10+` 在內部轉成數值 11 作門檻比較，但畫面仍顯示 `10+`。晾衫模式不計 AQHI。

| AQHI | 扣分（一般／運動） |
| --- | --- |
| 1–3 | 0／0 |
| 4–6 | 0／1 |
| 7 | 1／3 |
| 8–10 | 3／7 |
| 10+（內部值 11） | 5／10 |

## 5. 天氣警告規則

同一警告 family 只保留較嚴重的一項；不同 family 的扣分可以累加。`CANCEL` 項目會排除。表內仍依「一般／運動／晾衫」排列。

| 警告代碼 | 處理 |
| --- | --- |
| `WRAINB` 黑色暴雨 | 不另扣分，總分最高 1 |
| `TC8NE`、`TC8SE`、`TC8NW`、`TC8SW`、`TC9`、`TC10` | 不另扣分，總分最高 1 |
| `WTMW` 海嘯警告 | 不另扣分，總分最高 1 |
| `WRAINR` 紅色暴雨 | 扣 7／8／9 |
| `WRAINA` 黃色暴雨 | 扣 4／6／7 |
| `WTS` 雷暴 | 扣 4／7／7 |
| `TC3` 三號熱帶氣旋 | 扣 4／7／5 |
| `TC1` 一號戒備 | 扣 1／2／1 |
| `WMSGNL` 強烈季候風 | 扣 3／5／3 |
| `WHOT` 酷熱 | 扣 3／5／0 |
| `WCOLD` 寒冷 | 扣 3／3／1 |
| `WFNTSA` 新界北部水浸特別報告 | 扣 3／5／3 |
| `WL` 山泥傾瀉 | 扣 3／5／2 |
| `WFROST` 霜凍 | 扣 1／2／1 |
| `WFIREY` 黃色火災危險 | 扣 0／1／0 |
| `WFIRER` 紅色火災危險 | 扣 1／2／0 |

若收到程式不認識但正在生效的警告，該項不猜測扣分，而是把總分最高限制為 3 分。

## 6. 資料不完整與安全上限

只有 `fresh` 且有值的資料可進入數值評分。`stale`、`missing`、`failed`、`malformed` 不會被當成 0 風險。

| 情況 | 實際處理 |
| --- | --- |
| 任何與目前模式直接相關的非警告核心資料不可用 | 排除該數值，總分最高 7 |
| 警告來源失敗或過時 | 總分最高 7 |
| 警告快照成功，但至少一個警告項目驗證失敗 | 總分最高 3 |
| 存在未知的生效警告 | 總分最高 3 |
| 黑雨、八號或以上風球、`WTMW` | 總分最高 1 |
| 夜間 UV 不適用 | 不扣分、不限制最高分 |
| 只有附加 nowcast 失敗／過時／格式異常 | 不限制最高分，另由介面提示來源狀態 |

若目前模式沒有任何新鮮且相關的數值證據，也沒有可用的生效警告作證據，系統不會硬給 0、7 或 10 分，而是回傳 `score: null`，顯示「資料不足，暫未能評分」。

## 7. 資料新鮮度

邊界值本身仍視為新鮮；來源時間最多可比系統時間快 5 分鐘，超過才視為 future／不可用。

| 來源 | 最長資料年齡 |
| --- | --- |
| 即時天氣（雨量、氣溫、濕度、UV） | 90 分鐘 |
| AQHI | 3 小時 |
| 天氣警告快照 | 30 分鐘；按成功擷取時間判斷 |
| 本港天氣預報文字 | 12 小時 |
| 降雨臨近預報 | 來源更新後 24 分鐘 |

## 8. 地區值如何選取

地區選值會直接影響送入門檻的數字：

- 過去一小時雨量：選區時使用該區觀測；「香港整體」使用十八區最高值。
- 未來降雨：選區時使用該區靜態中心最近的官方格點；「香港整體」每個時段採十八區代表格點中的最高值，因此只代表香港部分地區的保守風險。
- 氣溫：地區依預設優先站次序選第一個有效觀測；「香港整體」使用香港天文台站。
- 濕度：所有地區使用香港天文台站。
- AQHI：地區使用設定的官方一般監測站；「香港整體」取所有一般監測站中最高的新鮮值，排除路邊站。
- UV、文字預報及警告：使用全港來源，不作地區化。

## 9. 分數如何變成結論

| 最終分數 | 結論 |
| --- | --- |
| 8–10 | 適合出門 |
| 4–7 | 可以出門，但需要準備 |
| 0–3 | 不建議戶外活動 |
| 無分數 | 資料不足，暫未能評分 |

因素另按安全及顯示優先序排序。最高優先因素成為首頁的一句原因摘要；去重後最多顯示三項行動建議。排序只影響說明與建議先後，不會改變數值計算。

## 10. 算分例子

### 例一：一般外出

- 過去一小時雨量 1 mm：降雨候選扣 1
- 未來 30 分鐘預測 3 mm：降雨候選扣 2，因此取 2，不再加觀測雨量的 1
- 氣溫 \(33\,^\circ\mathrm{C}\)：扣 3
- 濕度 \(85\%\)：一般模式不直接扣分，但與 \(33\,^\circ\mathrm{C}\) 共同觸發額外扣 1
- UV 8：扣 2
- AQHI 7：扣 1
- 無警告，資料完整

總扣分為 (2+3+1+2+1=9)，最終分數為 (10-9=1)，結論是「不建議戶外活動」。

### 例二：晾衫

- 過去一小時無雨：0
- 90–120 分鐘後預測 2.5 mm：較後 nowcast 候選扣 6
- 文字預報提及大雨：文字候選扣 7，因此降雨只取 7
- 濕度 85%：扣 3

總扣分為 (7+3=10)，最終分數為 0。氣溫、UV 及 AQHI 在晾衫模式不參與。

### 例三：資料缺失

- 一般外出按現有風險只扣 1 分，原始分數為 9
- 但氣溫資料缺失，觸發「非警告核心資料不完整」最高 7 分

最終分數為 \(\min(9,7)=7\)，結論是「可以出門，但需要準備」，而不是把缺失氣溫當作沒有高溫風險。

## 11. 程式碼審核觀察

1. 整體規則集中於 `thresholds.ts`，實際算分是純函式，邊界值、警告、資料缺失、降雨合併及三種模式已有單元測試覆蓋。
2. 「5 mm nowcast」與「大於 5 mm」是刻意不同的程式邊界；日後改文案或門檻時必須同步測試，否則容易誤寫成「5 mm 或以上」。
3. 一般外出把濕度視為高溫互動訊號，而不是獨立核心因素。只有新鮮氣溫達 33°C 或以上時，缺失、過時或格式異常的濕度才會列入 `ignoredFactors`，並把最高分限制為 7；較低氣溫下缺少濕度不會單獨限制分數。
4. nowcast 被定義為附加來源；其單獨失效不限制分數。此安排已有設計決策及測試，分數仍依即時觀測與警告產生，但使用者會在其他介面看到 nowcast 不可用提示。
5. 門檻是產品規則而非官方健康指引。若未來改動，應保留規則集中化、純函式及每個邊界值的測試，並在 `docs/DECISIONS.md` 記錄理由。
